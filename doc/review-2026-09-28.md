# Code review, 28 September 2026 — scores and the improvement plan

Three independent review passes over the whole repository (core packages;
React layer, widgets and plugins; builder, host, e2e and tooling), each
scoring code quality, extensibility, readability and testing 0–100, then
merged. Every finding was verified at the cited line. This file is the
plan that came out of it; the **Status** column is kept current as items
land (the commit that closed each one is named).

## Scores at the time of the review

| Dimension | Score | Core | React · widgets · plugins | Builder · host · e2e · tooling |
|---|---|---|---|---|
| Code quality | **78** | 80 | 80 | 77 |
| Extensibility | **72** | 82 | 73 | 64 |
| Readability | **81** | 86 | 84 | 73 |
| Testing | **58** | 76 | 40 | 66 |

Overall 72. The architecture is right and the core is well built; what
holds the score down is a testing floor with holes exactly where the timing
and data-loss risks are, and a set of correctness defects a linter and a
few tests would have caught. Target after the plan: every dimension in the
mid-80s.

## What the review called genuinely excellent — keep it that way

Path subscriptions derived from state identity (`store/index.ts`); the
reaction runner that keeps sync reactions inline (`engine/reactions.ts`);
the layout-engine conformance kit with its purity check
(`engine/layout-engine-checks.ts`); `usePort` memoised on the raw value;
`useRefresher` as a textbook `useEffectEvent`; the edit session as pure ops
replayed over live trees; `editedReaction`, which names the regression it
prevents and is pinned by a test; and the comments throughout — accurate,
explaining why, current after refactors.
